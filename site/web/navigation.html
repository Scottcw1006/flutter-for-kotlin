第 4 章 · 邏輯與架構對照

導航

Flutter 有兩層導航 API：內建的 Navigator 是一個頁面堆疊，用 push、pop 直接操作；go_router 則是以網址定義路由，適合有 deep link、多個分頁的 App。前者像直接操作 NavController 的 back stack，後者像 Navigation Compose 的 NavHost 加上型別安全的路由。

Navigator：push、pop 與回傳結果

說明

Navigator.of(context).push() 把新頁面放到堆疊最上面，pop() 回到上一頁。最方便的地方是：push 回傳一個 Future，新頁面 pop(結果) 時，前一頁的 await 就會拿到這個結果。

  • Navigation Compose 沒有內建的回傳值機制，要透過上一個 back stack entry 的 SavedStateHandle 傳遞。Flutter 的寫法就像一般的函式呼叫。
  • await 回來時這個畫面可能已經被關掉了，所以要先檢查 mounted 再 setState（第 2 章非同步提過）。
  • MaterialPageRoute 會依平台使用對應的轉場動畫。

要攔截返回鍵（例如「還沒存檔，確定離開？」），Compose 用 BackHandler，Flutter 用 PopScope(canPop: false, onPopInvokedWithResult: ...)。

實作主線：用 go_router 加上詳細頁

說明

待辦 App 現在有兩個畫面：清單和編輯頁。用 go_router 把它們定義成路由，點清單上的一筆就會開啟 /todo/:id。

巢狀的 navigation graph巢狀的 routes：子路由會疊在父路由的頁面上
  • context.push 會把頁面疊上去，context.go 則是「跳到這個網址」：堆疊會依照路由的巢狀結構重建。從清單進詳細頁用 push，從通知直接打開某一頁就用 go。
  • 因為路由就是網址，Android 的 deep link（App Links）設定好 intent filter 後，go_router 會直接解析，不用再自己對應。
  • 路徑字串不是型別安全的。想要像 Navigation Compose 那樣用類別定義路由，可以用 go_router_builder 產生代碼。

底部分頁

說明

底部導航列 NavigationBar 兩邊同名。切換分頁時要保留每個分頁的狀態，Flutter 最簡單的做法是 IndexedStack：它同時保留所有子元件，只顯示其中一個。

實際的 App 裡，每個分頁通常有自己的頁面堆疊。go_router 用 StatefulShellRoute.indexedStack 處理，相當於 Navigation Compose 切換分頁時的 saveState = true 與 restoreState = true。

共享元素轉場：Hero

說明

第 3 章動畫頁提到的共享元素動畫，Flutter 叫做 Hero：前後兩個頁面各包一個 Hero，給相同的 tag，push 或 pop 時它就會在兩個位置之間飛過去，不需要其他設定。Compose 的對應是 SharedTransitionLayout 加 Modifier.sharedElement()。
