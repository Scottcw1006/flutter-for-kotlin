版面配置與 constraints

Compose 和 Flutter 的版面配置演算法其實是同一套：constraints 由上往下傳、尺寸由下往上報，每個元件只測量一次。差別在於 Compose 用 fillMaxSize()、wrapContentSize() 這些 Modifier 把規則包得很好，平常感覺不到；Flutter 則把規則直接攤在你面前。弄懂它，就能看懂 Flutter 大部分的版面問題和錯誤訊息。

Constraints 往下、尺寸往上

說明

Flutter 的版面配置只有三條規則：

  1. 父層把 constraints（最小與最大的寬、高）傳給子元件。
  2. 子元件在這個範圍內決定自己的尺寸，回報給父層。
  3. 父層決定子元件的位置。子元件不知道自己在哪裡，也不能超出 constraints。

最小值等於最大值時稱為緊（tight）的 constraints：子元件沒有選擇，只能是這個尺寸。最小值是 0 時稱為鬆（loose）的 constraints：子元件可以在 0 到最大值之間自己決定。

所以 Container(width: 100) 的 100 只是一個希望，最後的尺寸還是由父層的 constraints 決定。切換下面的三個選項，方塊裡會顯示它實際收到的 constraints：

  • LayoutBuilder 對應 BoxWithConstraints，可以拿到父層給的 constraints 再決定要畫什麼。
  • Compose 的 Modifier.size() 一樣會被 constraints 限制住，所以 fillMaxSize().size(100.dp) 裡的 100 也沒有作用，跟「直接放」是同一件事。
  • 兩邊最大的差別在預設值：Compose 的 Box 給子元件的永遠是鬆的 constraints；Flutter 有很多元件會給緊的 constraints，例如畫面最外層、Expanded、SizedBox，以及 Column 設成 stretch 時的寬度。

Expanded、Flexible 與無界的 constraints

說明

Expanded 對應 Modifier.weight()，flex 參數就是權重。Flexible 對應 weight(1f, fill = false)：最多分到這麼多空間，但子元件可以比較小。

Row、Column 的運作方式是：先用無界（最大值是無限大）的主軸 constraints 測量沒有 Expanded 的子元件，再把剩下的空間分給 Expanded。這解釋了 Flutter 最常見的錯誤：

在 Column 裡直接放 ListView，會出現「Vertical viewport was given unbounded height」錯誤。ListView 想盡量長高，但 Column 給它的高度上限是無限大，它無法決定自己的尺寸。解法是把 ListView 包在 Expanded 裡，讓它填滿剩下的空間。

Compose 也有同樣的規則：LazyColumn 在 Column 裡用 Modifier.weight(1f) 填滿剩下的空間，對應的就是 Expanded。另一個相關的崩潰是把 LazyColumn 放進 Column(Modifier.verticalScroll())：可捲動的容器給的高度上限是無限大，weight 在這裡也不會生效。兩邊的解法都是不要巢狀捲動，改成單一的列表（Flutter 用 CustomScrollView 加 slivers，Compose 用 LazyColumn 的 item { }），或給內層列表固定高度。

第一節提到的黃黑斜紋 overflow，也是同樣的機制：Row 先用無界寬度測量長文字，文字量出來比可用寬度還寬，就超出了。把它包進 Expanded，它拿到的就是有上限的寬度，文字會自動換行。

Box 與 Stack

說明

把元件疊在一起：Compose 用 Box，Flutter 用 Stack。子元件的對齊方式則對應如下：

ComposeFlutter
Box(contentAlignment = …)Stack(alignment: …)
Modifier.align(Alignment.BottomEnd)Align(alignment: Alignment.bottomRight, child: …)
Modifier.align() 加上 offset()Positioned(right: -4, bottom: -4, child: …)
Modifier.matchParentSize()Positioned.fill(child: …)

Flutter 的 Stack 預設會裁切超出範圍的子元件（clipBehavior: Clip.hardEdge），Compose 的 Box 則不會。這裡的紅色標籤超出頭像外，所以要設成 Clip.none，否則右下角會被切掉。

說明

  • LayoutBuilder 看的是父層給這個元件的空間，適合做可以放在任何地方的元件。
  • 要看整個畫面的大小（例如手機和平板用不同的版面），用 MediaQuery.sizeOf(context)，對應 Compose 的 LocalConfiguration 或 window size class。

用 MediaQuery.sizeOf(context)，不要用 MediaQuery.of(context).size。後者在任何 MediaQuery 資料變動時都會重建（例如鍵盤彈出、系統字體大小改變），前者只在尺寸改變時才重建。
