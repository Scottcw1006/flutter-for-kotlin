文字輸入與表單

文字輸入是 Compose 與 Flutter 寫法差最多的元件之一：Compose 的文字存在你自己的 state 裡，Flutter 的文字則存在一個 controller 物件裡。這一頁從這個差別開始，再看表單驗證、焦點與鍵盤，最後修正待辦 App 編輯頁的一個初始值問題。

誰持有文字：state 與 controller

說明

Compose 的 TextField(value, onValueChange) 是典型的 state hoisting：文字存在外面，TextField 只負責顯示，使用者輸入時回報新的值。Flutter 的 TextField 則是把文字交給 TextEditingController 管理，TextField 直接讀寫它：

做什麼ComposeFlutter
文字存在哪自己的 mutableStateOf("")TextEditingController
讀取目前的文字讀 statecontroller.text
從程式修改文字改 statecontroller.text = …、controller.clear()
文字改變時更新其他 UIstate 改變會自動重組用 ListenableBuilder 監聽 controller，或用 onChanged 搭配 setState
釋放不需要在 dispose() 呼叫 controller.dispose()

所以 controller 一定要放在 State 的欄位裡，不能在 build() 裡建立：每次重建都會產生一個新的 controller，使用者輸入的內容就消失了。

只需要在送出時拿到文字的簡單情況，也可以不用 controller，改用 onChanged 把值存起來。另外，Compose 新版的 TextFieldState（rememberTextFieldState()）其實就是 controller 的寫法，用過它的話，Flutter 的 controller 會很好理解。

鍵盤遮擋

說明

Flutter 範本的 AndroidManifest.xml 已經設定 windowSoftInputMode="adjustResize"，而 Scaffold 預設 resizeToAvoidBottomInset: true：鍵盤跳出來時，body 的可用高度會變小，作用就像 Compose 的 Modifier.imePadding()。

  • 表單要能捲動：高度變小之後，固定高度的 Column 會放不下，出現第 3 章提過的 overflow 斜紋。所以表單通常用 ListView 或 SingleChildScrollView 包起來，範例的 SignUpForm 就是用 ListView。
  • 點空白處收起鍵盤：Flutter 不會自動處理。常見做法是在 TextField 的 onTapOutside 呼叫 FocusScope.of(context).unfocus()。

controller 的初始值從哪裡來

說明

編輯畫面常常要先填入既有的資料，例如待辦的標題。controller 的初始值只會在建立時用一次，之後就由使用者的輸入決定。所以有兩個原則：

  • 不要在 build() 裡把資料塞回 controller：每次重建都會蓋掉使用者正在輸入的內容。
  • 等資料準備好才建立 controller：資料還在載入時就建立，初始值會是空的，之後也不會自動補上。

Compose 的對應寫法是 remember(todo.id) { mutableStateOf(todo.title) }，同樣放在資料載入完成之後才組合的 composable 裡。第 4 章替待辦 App 加上編輯頁時，就會用這個方式處理。
