K→FFlutter for Kotlin 開發者

開始之前

用你會的 Kotlin，學會 Flutter

這份教學寫給已經會 Kotlin、寫過 Jetpack Compose 的 Android 工程師。目標有兩個：用你已經有的知識，快速建立 Flutter 的對應觀念；最後能自己用 Flutter 寫出一個新的 Android App，並且知道它怎麼跟原生 Android、iOS 串接，以及怎麼打包上架。

怎麼閱讀這份教學

大部分小節都是同一個格式：先說明觀念，接著把同一個畫面的 Compose 寫法與 Flutter 寫法並排，最下面是 Flutter 程式碼實際執行的畫面。畫面可以直接點擊、輸入，不是截圖。

Compose（Kotlin）：你熟悉的寫法 Flutter（Dart）：要學的寫法

網頁上的程式碼都是從 repo 裡真正會編譯、會執行的原始碼自動擷取出來的。Compose 程式碼來自 samples/android，CI 會實際編譯；Flutter 程式碼就是驅動畫面的那一份。所以程式碼不會跟畫面對不上，也不會過時。

實作主線：待辦清單 App

光看對照表學不會組裝一個完整的 App。所以每一章的最後，都會替同一個待辦清單 App 加上一塊功能：第 3 章是畫面，第 4 章是狀態管理、網路與儲存，第 6 章把它嵌進既有的 Android App，第 8 章打包上架。

這個 App 是 repo 裡的 todo_app/，是一個完整的 Flutter 專案。網頁上的待辦 demo 就是直接執行它的程式碼。

準備環境

在 macOS 上可以用 Homebrew 安裝 Flutter SDK，裝完後用 flutter doctor 檢查 Android toolchain：

brew install --cask flutter
flutter doctor
flutter doctor --android-licenses

Android toolchain 那一行要全部打勾。最常見的缺漏是「cmdline-tools component is missing」：Android Studio 預設不一定會安裝它，在 SDK Manager 的 SDK Tools 分頁勾選 Android SDK Command-line Tools 即可。少了它，開發時還能正常執行，但 flutter build appbundle 會在最後一步失敗（exit code 1），CI 或發佈腳本會判定建置失敗。也因為少了它，flutter doctor --android-licenses 無法執行。

Android Studio 可以繼續用，只要另外安裝 Flutter 與 Dart 兩個 plugin。也可以改用 VS Code 搭配官方的 Flutter extension。

跑起待辦 App：在 todo_app/ 目錄執行 flutter run，選擇已開啟的 Android 模擬器。改了程式碼後按 r 是 hot reload，效果類似 Compose 的 Live Edit，但會保留 App 的狀態。
