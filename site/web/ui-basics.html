第 3 章 · UI 對照

從 Composable 到 Widget

Compose 和 Flutter 都是宣告式 UI，心智模型幾乎一樣：描述「資料長這樣時，畫面長這樣」，資料變了，框架就重新產生畫面。真正要調整的習慣只有兩個：Compose 的 UI 單位是函式，Flutter 是類別；Compose 用 Modifier 修飾元件，Flutter 則是用 widget 包 widget。

第一個 Widget

說明

一個 @Composable 函式對應到一個 StatelessWidget 子類別，函式本體對應到 build() 方法：

  • 參數變成欄位：Compose 的函式參數在 Flutter 裡是 final 欄位，再由建構子填入。required this.name 是 Dart 的具名參數語法：寫在 {} 裡的參數呼叫時要寫名字，加上 required 才是必填。
  • Widget 是不可變的「設定」：它不是畫面上的元件本身，而是一份描述。所以欄位全是 final，建構子也盡量宣告成 const。const 的 widget 在編譯期就建好，重建時框架可以直接跳過，作用接近 Compose 對 stable 參數的 skip。
  • 主題：MaterialTheme.typography 對應 Theme.of(context).textTheme。context 是這個 widget 在樹中的位置，第 5 章會詳細說明。
  • Modifier 參數：Compose 慣例是每個元件都開放 modifier 參數，Flutter 沒有這個慣例。要加外距，就在呼叫端外面包一層 Padding。

預設對齊不一樣：Compose 的 Column 預設靠左（Alignment.Start），Flutter 的 Column 預設置中（CrossAxisAlignment.center）。所以 Flutter 版要多寫 crossAxisAlignment: CrossAxisAlignment.start，畫面才會一樣。

Column、Row 與 weight

說明

名字一樣，概念也一樣，差在參數名稱。Flutter 統一用「主軸」（排列方向）與「交叉軸」（垂直於排列方向）來命名，Row 和 Column 的參數名稱完全相同：

ComposeFlutter
horizontalArrangement（Row）
verticalArrangement（Column）		mainAxisAlignment
verticalAlignment（Row）
horizontalAlignment（Column）		crossAxisAlignment
Arrangement.spacedBy(12.dp)spacing: 12
Modifier.weight(1f)Expanded(flex: 1, child: …)
Modifier.weight(1f, fill = false)Flexible(child: …)

contentDescriptionsemanticLabel

注意 weight 從 Modifier 變成了外層 widget：在 Flutter 裡，「我在父層佔多少空間」這件事一樣是靠包一層 Expanded 來表達。

Flutter 的 Row 預設撐滿主軸（mainAxisSize: MainAxisSize.max），所以不需要 fillMaxWidth()。交叉軸預設置中，剛好就是 Alignment.CenterVertically。

把上面的 Expanded 拿掉，長名字會超出 Row 的寬度，debug 模式下會出現黃黑相間的斜紋警告（overflow）。Compose 在這種情況下會默默把右邊的元件擠掉，Flutter 則會直接顯示出來。這是 Flutter 版面配置規則（constraints）的結果，下一節會說明。

Modifier 去哪了？

說明

Flutter 沒有 Modifier。Compose 裡每一個 modifier，在 Flutter 都是一個獨立的 widget，一層一層包在外面。對應規則很簡單：

Modifier 鏈由左到右 ＝ Widget 由外到內。兩邊的「順序很重要」完全是同一件事：先 padding 再 background，就是 Padding 包在色塊外面，所以留白在色塊外。

Compose ModifierFlutter Widget
.padding()Padding
.background()ColoredBox、DecoratedBox、Material
.clip(RoundedCornerShape())ClipRRect
.clickable { }InkWell（有水波紋）、GestureDetector（沒有）
.size()、.fillMaxWidth()SizedBox、SizedBox(width: double.infinity)
.alpha()Opacity
.border()DecoratedBox(decoration: BoxDecoration(border: …))

每層都包一個 widget 很快就會縮排很深，所以 Flutter 提供 Container 當捷徑：一次設定 margin、padding、decoration、寬高與對齊，內部其實就是幫你組合好上面那些 widget。

InkWell 的水波紋是畫在離它最近的祖先 Material 上。如果改用 Container(color: …) 當背景，色塊會蓋住水波紋，點了看起來沒反應。所以要有背景色又要有水波紋時，用 Material(color: …) 當背景，或是改用 Ink。

縮排太深時，做法跟 Compose 把一段 UI 抽成新的 @Composable 函式一樣，在 Flutter 就抽成一個新的 widget 類別。不要抽成回傳 Widget 的方法，第 5 章會解釋原因。

狀態：remember 與 StatefulWidget

說明

Compose 用 remember { mutableIntStateOf(0) } 讓值在重組之間保留下來。Flutter 的做法是把 widget 拆成兩個類別：

  • StatefulWidget：跟其他 widget 一樣是不可變的設定，每次父層重建都會產生新的物件。
  • State：由框架保存的長壽物件，畫面重建時不會被丟掉。狀態就放在它的欄位裡，作用相當於 remember 在 Compose 內部保存值的位置。

最大的差別在於怎麼通知框架狀態變了。Compose 的 MutableState 會自動追蹤「誰讀了這個值」，寫入時自動重組。Flutter 不做追蹤，改值時要包在 setState(() { … }) 裡，明確告訴框架「這個 State 要重建」，框架就會重新呼叫 build()。

直接寫 _count++ 而沒有包在 setState 裡，值確實會變，但畫面不會更新。這是從 Compose 轉過來最常犯的錯。

其他要注意的對應：

  • Button 對應 FilledButton。Flutter 的 ElevatedButton 是另一種有陰影的樣式，名字容易搞混。
  • onClick 對應 onPressed，按鈕內容的 lambda 對應 child。
  • Compose 的 Row 預設包住內容，Flutter 的 Row 預設撐滿。要讓兩顆按鈕靠在一起置中，就要寫 mainAxisSize: MainAxisSize.min。
  • 反過來，兩邊的 Column 在交叉軸（寬度）都只包住內容。Compose 版寫了 fillMaxWidth() 讓內容在整個寬度置中，Flutter 版就在最外層包一個 SizedBox(width: double.infinity)。
  • 重建範圍是整個 build()。狀態放得越外層，每次重建的範圍越大，所以會改變的部分要拆成小 widget，原則跟 Compose 縮小重組範圍一樣。

rememberSaveable 對應 Flutter 的 RestorationMixin，但實務上很少用。畫面層級的狀態通常會交給狀態管理套件，角色就像 ViewModel 加 StateFlow，這部分在第 4 章說明。

實作主線：待辦項目元件

說明

用本章學到的東西，替待辦清單 App 做出每一列的元件。左邊是你可能會在 Compose 寫出的 TodoItem，右邊是 todo_app/lib/widgets/todo_tile.dart 裡的 TodoTile：

  • ListItem 對應 ListTile：leadingContent、headlineContent、trailingContent 分別對應 leading、title、trailing。
  • 回呼型別 () -> Unit 對應 VoidCallback，它其實就是 void Function() 的 typedef。
  • TextStyle.copy() 對應 copyWith()。textTheme.bodyLarge 在 Dart 裡是可為 null 的型別，所以要寫 ?.copyWith。
  • 點整列開啟詳細頁：Compose 用 Modifier.clickable，ListTile 則直接提供 onTap 參數。詳細頁在第 4 章的導航加上。
