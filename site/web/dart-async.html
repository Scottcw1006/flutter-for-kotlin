非同步：Future 與 Stream

Kotlin 的 coroutines 是函式庫，要自己決定 scope 和 dispatcher；Dart 的非同步則是語言內建，而且建立在單執行緒的 event loop 上。所以 Dart 少了很多概念：沒有 dispatcher、沒有 scope，也沒有 structured concurrency。寫起來比較簡單，但取消和生命週期要自己注意。

Future 與 async/await

說明

標上 async 的函式會回傳 Future，在裡面可以用 await 等待其他 Future，寫起來和 suspend 函式幾乎一樣。最大的差別在於：

  • 呼叫 async 函式的那一刻，它就開始執行了，不管你有沒有 await。不 await 就等於「發射後不管」，相當於不用寫 launch 的 launch { }。
  • Kotlin 的 coroutineScope 會等所有子 coroutine 結束，Dart 不會。對照兩邊的輸出：Dart 先印出「futures() 結束」，「稍後取得」是在函式結束之後才出現的。
  • 並行等待多個 Future 用 Future.wait()，對應 awaitAll()。

忘記 await 是很常見的 bug，而且編譯器預設不會警告。建議在 analysis_options.yaml 開啟 unawaited_futures 規則；真的不想等待時，用 dart:async 的 unawaited(f()) 明確標示。

錯誤處理與取消

說明

錯誤處理和同步程式碼一樣用 try/catch。只捕捉特定型別時寫 on 型別 catch (e)，對應 Kotlin 的 catch (e: 型別)。

取消就完全不同了。Future 沒有取消機制：timeout() 只是「不再等待」，原本的工作會繼續跑完。看輸出的最後一行：逾時之後 mayFail 還是印出了「跑完了」。Kotlin 的 withTimeout 則會真的取消它。

這在 UI 程式碼裡很重要。Compose 的 LaunchedEffect 和 viewModelScope 會在離開畫面時自動取消；Flutter 不會，await 回來時這個 widget 可能已經被移除了。所以在 State 裡 await 之後、呼叫 setState 或使用 context 之前，要先檢查 if (!mounted) return;。

說明

說明

StreamBuilder 對應 collectAsState()，FutureBuilder 對應 produceState。它們的 builder 會拿到一個 AsyncSnapshot，除了最新的 data，還有 connectionState（等待中、進行中、已結束）和 error，比 Compose 的 State 多了「已結束」與「錯誤」的資訊。

不要在 build() 裡建立 Stream 或 Future。build() 隨時可能重新執行，每次都會產生新的 Stream，倒數就會一直重來。要像這裡一樣放在 State 的欄位，或在 initState() 建立，這就是 Compose 裡 remember(round) { countdown(5) } 做的事。

執行緒與 isolate

說明

Dart 的程式碼跑在單執行緒的 event loop 上。網路、檔案這類 I/O 由底層非同步處理，await 時 event loop 會去處理別的事，所以不需要 Dispatchers.IO。

但如果是吃 CPU 的運算（解析大型 JSON、影像處理），它會卡住 event loop，畫面就會掉幀。這時要把工作丟到另一個 isolate，相當於 withContext(Dispatchers.Default)：

  • Isolate.run(() => ...) 是 Dart 的標準做法；Flutter 的 compute(函式, 參數) 是它的包裝，在網頁上也能用。
  • isolate 之間不共享記憶體，參數和結果會被複製過去。不用擔心 race condition，但大量資料的傳遞有成本。

網頁不支援 isolate，所以這裡的 compute 其實是在同一條執行緒上執行的。在 Android 和 iOS 上，它會在另一個 isolate 中執行，計算期間 UI 不會卡住。

Stopwatch()..start() 裡的 .. 是 cascade 運算子：對同一個物件連續呼叫方法，並回傳物件本身，效果類似 Kotlin 的 apply { start() }。
