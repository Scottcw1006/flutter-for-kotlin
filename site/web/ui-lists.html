列表

Compose 用一套 LazyColumn { items() } DSL 處理所有列表；Flutter 則依用途分成好幾種建構子：ListView、ListView.builder、ListView.separated、GridView.builder。概念完全一樣：只建立畫面上看得到的項目，捲動時再建立新的。

itemBuilder 會在項目即將出現在畫面上時被呼叫，參數是 index，相當於 items(1000) { index -> } 的 lambda。separated 版本只會在項目之間加分隔線，最後一項後面不會有。

ListView(children: [...]) 看起來比較簡單，但它會一次建立所有子元件，跟 Column 加 verticalScroll 一樣。項目只有幾個時沒關係，資料筆數不固定時就要用 ListView.builder。

橫向列表與 Grid

說明
  • LazyRow 對應 ListView(scrollDirection: Axis.horizontal)。
  • LazyVerticalGrid(GridCells.Fixed(3)) 對應 GridView.builder 搭配 SliverGridDelegateWithFixedCrossAxisCount(crossAxisCount: 3)。GridCells.Adaptive(120.dp) 則對應 SliverGridDelegateWithMaxCrossAxisExtent(maxCrossAxisExtent: 120)。
  • Flutter 的 grid 格子預設是正方形（childAspectRatio: 1），Compose 要自己加 aspectRatio(1f)。

橫向的 ListView 一定要給高度。Compose 的 LazyRow 會自動配合項目的高度；Flutter 的 lazy 列表還沒建立所有項目，不知道它們有多高，所以在 Column 裡要包一個 SizedBox(height: 56)，否則就會遇到上一頁提到的無界 constraints 錯誤。

Key：讓狀態跟著項目走

說明

列表中的每一列都有自己的狀態（這裡是勾選框，存在 State 裡，就像 item 內的 remember）。資料變動時，框架要知道「新的第幾列對應到舊的第幾列」，才能把狀態留給正確的項目。

沒有 key 時，Flutter 是依位置配對的：刪掉第一項後，原本第一列的狀態會留給新的第一列。Compose 的 LazyColumn 沒有給 key 時也是一樣。

  • ValueKey(fruit) 對應 items(list, key = { it })。key 必須穩定且唯一，通常用資料的 id。
  • 不要用 index 當 key（等於沒有 key），也不要每次 build 都產生新的 UniqueKey()（每次重建都會丟掉狀態）。
  • late var _checked = widget.initiallyChecked;：在欄位初始值裡讀取 widget 要加 late，因為物件建立時 widget 還沒被設定。

Key 的運作原理在第 5 章「Key 與 const」會用 widget 樹詳細說明。

實作主線：待辦清單改用 ListView.builder

說明

待辦清單用 ListView.builder 建立每一列，並以 todo.id 作為 ValueKey：刪除或重新排序時，勾選動畫這類狀態才會跟著正確的項目。程式碼在 todo_app/lib/screens/todo_list_screen.dart。

右邊外層的 switch (todos) 是第 4 章狀態管理加上的：清單資料改由 Riverpod 提供，要依照「已載入、錯誤、載入中」三種狀態分別顯示。這一頁只要看 AsyncData 那一支裡的 ListView.builder 就好。
