嵌入原生 View

上一頁是把 Flutter 放進 Android；這一頁反過來，在 Flutter 畫面裡放一個 Android 的 View。這個功能叫 platform view，作用就像 Compose 的 AndroidView：地圖、WebView、廣告、相機預覽這類只有原生版本的元件，都是靠它顯示在 Flutter 畫面裡。

常用的原生元件都已經有包好的套件：google_maps_flutter、webview_flutter、google_mobile_ads、camera。它們內部就是用本頁的機制實作的。自己寫 platform view，通常是為了公司既有的自訂 View，或是某個只有 Android SDK 的第三方元件。

範例：在 Flutter 裡放一個 Compose 元件

說明

範例專案 samples/native_bridge/ 的最後一張卡片，嵌入了一個用 Compose 寫的計數按鈕。按下 Compose 按鈕，Flutter 這邊的文字也會同步更新：

需要三個部分：

  1. Kotlin 端的 PlatformView：包住真正的 Android View，並在 dispose() 釋放資源。
  2. PlatformViewFactory：Dart 端每建立一個實例，就呼叫一次 create()；它的 args 是 Dart 傳來的初始參數。
  3. Dart 端的 AndroidView：用 viewType 字串指定要建立哪一種 View。iOS 上改用 UiKitView，原生端的 SwiftUI 版本見第 7 章。

工廠要在引擎上註冊，名稱與 Dart 端的 viewType 相同（完整的 MainActivity 在上一頁）：

flutterEngine.platformViewsController.registry.registerViewFactory(
    "f4k/native-counter",
    ComposeCounterFactory(NativeEvents(messenger)),
)

嵌入 ComposeView 的陷阱

說明

ComposeView 被加進畫面時，會沿著 View 樹往上找 LifecycleOwner 和 SavedStateRegistryOwner。ComponentActivity 會在 setContentView 時設定好這些，但 FlutterActivity 繼承的是一般的 Activity，沒有設定。範例實際測試的結果，App 一打開就崩潰：

java.lang.IllegalStateException: ViewTreeLifecycleOwner not found from io.flutter.embedding.android.FlutterView

解法是讓 MainActivity 改為繼承 FlutterFragmentActivity，它是 FragmentActivity（也就是 ComponentActivity）的子類別。嵌入一般的 Android View（例如 TextView、MapView）沒有這個問題。

與原生 View 互相溝通

說明
  • Dart → 原生，只在建立時：creationParams，經過 creationParamsCodec 編碼。範例用它傳入標題文字。
  • 之後的雙向溝通：用前一頁的 channel 或 Pigeon。範例用 Pigeon 的 @FlutterApi，讓 Compose 按鈕呼叫 Dart 端的 onNativeButtonClicked。

範例畫面上只有一個實例，所以全域的 channel 就夠用。同一個畫面有多個實例時，要讓每個實例用不同的 channel：AndroidView 的 onPlatformViewCreated 會給你 viewId，Kotlin 端的 create() 也拿得到同一個 viewId。手寫 channel 時把它加進名稱（例如 f4k/counter_$viewId）；Pigeon 則用 messageChannelSuffix 參數。

合成模式：原生 View 是怎麼畫進 Flutter 的

說明

Flutter 畫面是一整塊自己繪製的 Surface（第 1 章），而 Android View 由系統繪製，兩者要疊在一起並不簡單。Flutter 提供幾種合成模式，由 Dart 端用哪個 API 決定：

模式Dart 端寫法特性
Texture Layer Hybrid Composition（TLHC）AndroidView（本範例）原生 View 畫到一個 texture，再由 Flutter 合成。效能好，Flutter 畫面不受影響。不支援 SurfaceView，遇到時會退回其他模式
Hybrid CompositionPlatformViewLink ＋ PlatformViewsService.initExpensiveAndroidView原生 View 直接放進 Android 的 View 階層，相容性最好（地圖、影片這類用 SurfaceView 的元件）。代價是 Flutter 的繪製也會受影響，整體幀率可能下降
Virtual Display舊的退回選項畫到虛擬螢幕再當成 texture。鍵盤輸入、無障礙等功能有限制，新代碼不建議使用

大多數情況直接用 AndroidView 就好。原生元件畫面不正常（例如黑屏、不會更新）時，再改用 Hybrid Composition。

成本與限制

說明
  • 每個 platform view 都有額外成本：不要把它放在會捲動的長列表裡大量建立。能用 Flutter widget 做到的 UI，就用 widget。
  • 大小由 Flutter 決定：platform view 和一般 widget 一樣受 constraints 限制（第 3 章）。範例用 SizedBox(height: 140) 給固定高度，原生 View 自己的 wrap_content 不會影響 Flutter 的版面。
  • 手勢衝突：原生 View 放在可捲動的 Flutter 容器裡時，拖曳手勢預設會被 Flutter 搶走。用 AndroidView 的 gestureRecognizers 指定哪些手勢交給原生 View，例如讓地圖可以拖曳。
  • 生命週期：widget 從樹上移除時，Flutter 會呼叫 PlatformView.dispose()。在這裡釋放資源，例如範例的 disposeComposition()、MapView 的 onDestroy()。

反方向「在 Compose 裡放一小塊 Flutter UI」則是上一頁 add-to-app 的範圍：用 AndroidView 包住 FlutterView，再 attach 到一個 FlutterEngine。
